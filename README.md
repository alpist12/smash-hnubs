# HNUBS SMASH — 방송국 부수기

실행 가능한 Vite + React + TypeScript 3D 물리 웹게임입니다. Three.js, React Three Fiber/Drei, Rapier, Zustand를 사용합니다. 게임 실행에 API 키·유료 서비스·백엔드·외부 폰트 서버가 필요하지 않습니다.

## 실행

Node.js 22.12 이상 또는 24 이상에서 이 폴더를 터미널로 열고 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다. 같은 Wi-Fi의 휴대폰은 터미널에 표시된 Network 주소를 이용합니다. Windows 방화벽의 해당 로컬 개발 서버 접근 허용이 필요할 수 있습니다.

```sh
npm test          # 배치·모델 유효성 / 중복 점수 / 저장 차단 / 복구 / 무기 감쇠 / 효과·파편 제한
npm run build    # TypeScript 검사 및 정적 빌드
npm run preview  # 빌드 결과 확인 (기본 4173 포트)
npm run export:model  # Blender용 가구 모델 GLB 재생성
npm run import:layout # Blender에서 내보낸 배치를 검증·적용하고 게임 재빌드
npm run editor       # 이 컴퓨터에서만 여는 제작용 배치 편집기
```

`dist/`는 정적 호스팅에 올릴 수 있는 빌드입니다. 파일을 더블클릭하는 `file://` 방식 대신 HTTP로 실행해야 합니다. 공개 배포는 수행하지 않았습니다.

## 공간 재현 기준

**사용자가 나중에 제공한 평면도와 색상 설명이 가구 위치의 우선 기준입니다.** 처음 생성한 실내 시안은 사용자가 실제와 다르다고 지적했으므로 구현 기준에서 제외했습니다.

- 초록: 책상 7개. 위쪽 왼편 1개, 위쪽 오른편 2개, 오른편 세로 1개, 아래쪽 1개, 오른쪽 아래 2개.
- 파랑: 위쪽 왼편 소파 및 오른편 세로 소파.
- 빨강: 중앙의 긴 공용 책상.
- 검정: 중앙 책상 위·아래·왼편의 긴 의자/소파.
- 노랑: 좌측 벽과 뒤쪽 벽의 문 2개.
- 주황: 아래쪽 오른편 벽의 빔프로젝터 스크린. 창문으로 해석하지 않았습니다.

원본 파노라마는 회색/푸른 회색 흡음판, 밝은 목재 하부 마감, 블라인드, 모니터·노트북, 붉은 소파와 낡은 아이보리 소파, 목재 사물함의 형태·재질 참고로 사용했습니다. 사람은 모델링하지 않았습니다.

추가로 제공한 전체 사진 `KakaoTalk_20261112_023836886.jpg`에 맞춰 스크린 쪽 벽의 상부 목재 띠–중간 회색 흡음판–하부 목재 마감, 큰 롤스크린의 흰 케이스·검은 테두리·하단 봉을 반영했습니다. 검은 게시판을 스크린 오른쪽 벽으로 옮기고, 사이의 금속 선반과 분홍 쿠션·전화기·보관 상자를 추가했습니다. 가구 평면 배치는 제공된 도면을 유지하며 각 치수는 추정값입니다. 우측 카메라 버튼의 **스크린 쪽 보기**로 해당 벽을 확인할 수 있습니다.

실측이 없어 **14 × 9 × 2.8m는 추정값**입니다. 공간이 작다는 피드백에 따라 10.5 × 5.8m에서 바닥 면적을 약 두 배로 넓혔습니다. 책상·테이블·모니터도 크게 만들었고, 모니터 방향에 맞춰 키보드·마우스와 의자 방향을 맞춘 뒤 의자를 책상에서 뒤로 뺐습니다. **수납장 사진의 방향에 대한 최종 정정은 첨부 평면도의 왼쪽 벽**입니다. 기본 배치에서 큰 목재 수납장 2개·작은 사물함·냉장고는 왼쪽 벽을 향하고, 스크린은 아래쪽 주황선에 있습니다. 칸막이는 오른편 작업 책상에 부착했습니다. 위쪽 두 구역에는 임시 기술부스·아나부스를 추가했고 외부 건물은 만들지 않았으며, 실제 치수와 소품의 세부 형상은 교체 가능한 추정입니다. 사진 측량이나 실사 스캔 결과가 아닌, 세부 부품을 가진 절차적 3D 모델입니다.

## 조작

| 기능 | PC | 모바일 |
|---|---|---|
| 공격 | 물체/바닥 클릭 | 물체/바닥 탭 |
| 회전 | 왼쪽 드래그 | 한 손가락 드래그 |
| 확대 | 휠 | 두 손가락 확대 |
| 이동 | 오른쪽 드래그 | 두 손가락 이동 |
| 무기 | 1 배트 / 2 폭탄 / 3 레이저 / 4 음파 | 하단 무기 바 |
| 레이저 지속 공격 | 누른 상태로 조준 | 누른 상태로 조준 |
| 복구 / 기본 시점 | R / F | 우측 버튼 |

레이저 공격 중에는 한 손가락/왼쪽 드래그가 조준에 사용됩니다. 다른 무기에서 카메라를 회전하거나 우측 시점 버튼을 이용하세요. 우측 버튼에는 전체를 위에서 보기, 시점 초기화, 스크린 쪽 보기, 맵 복구, 사운드가 있습니다. 벽은 카메라 방향에 맞춰 자동 절단되며 별도로 끌 수도 있습니다. 천장은 기본적으로 숨깁니다. 천장 조명을 공격하려면 `천장`을 켜세요.

## 구현 기능

- 자유 파괴 모드, 시간제한 없음. 기본 배치의 점수 대상은 95개이며, 제작자가 복사·삭제한 개수에 따라 점수 대상과 파괴율도 함께 바뀝니다.
- 책상 상판·다리·서랍, 모니터 화면·목·받침대, 의자 좌판·등판·헤드레스트·오발 다리·바퀴, 소파 프레임·팔걸이·쿠션, 수납장 문·선반·손잡이.
- 게시판 아래 간식대에는 컴퓨터 대신 큰 커피머신·전자레인지·간식 봉지·컵을 배치했습니다. 왼쪽 벽에는 긴 수납장과 냉장고를, 오른편 책상에는 회색 칸막이를 반영했습니다.
- 추가 세부 사진에 맞춰 팔걸이 없는 4분할 곡선 붉은 소파, 나무 좌판·검은 철제 다리의 긴 벤치 2개, 프린터·삼각대, 4연 창문과 블라인드·벽시계·일정판·타일 카펫을 반영했습니다. 책상과 중앙 테이블·모니터를 확대하고 모니터 방향은 이전 배치에서 180도 반전했습니다. 사진 속 인물은 재현하지 않았습니다.
- 각 가구의 질량·강도·충돌 손상 임계값. 충격 이동 → 전도 → 손상 표시 → 파손 → 개별 부품 파편.
- 배트의 근접 충격, 0.8초 지연 폭탄과 거리별 감쇠, 지속 레이저, 원형 방송국 음파.
- 충격파·먼지·배트 스윙·레이저 빔·카메라 흔들림·선택 가능한 합성 사운드.
- 타격감 피드백에 따라 배트·폭탄·음파의 충격을 키우고, 큰 상판·문짝을 우선 파편으로 남기며, 기본 시점을 더 가깝게 조정했습니다.
- 공격과 충돌에 의한 손상, 같은 물체의 점수 1회 지급, 파괴율, 점수 숫자 애니메이션, 최고 점수 저장.
- 맵 복구 시 물리 월드·누적 손상·파편·설치된 폭탄·점수를 함께 초기화. 최고 점수는 유지.
- 초기 물체 수면, 단순한 복합 충돌체, 반복 벽 패널 InstancedMesh, 공유 지오메트리·재질·텍스처, 가구별 최대 28조각(가벼움 16조각), 전체 물리 파편 최대 160개(가벼움 70개), 파편 수명 7~11초, 효과 18개 상한.
- 기본 고화질: DPR 1.5~2, 2048px 부드러운 그림자, 512px 표면 텍스처와 굴곡, 목재 결·패브릭·가죽 PBR 재질, 외부 HDR 파일이 필요 없는 반사 조명, 매끈한 가구 모서리와 원형 부품. 저사양 기기는 그래픽 품질을 가벼움으로 전환할 수 있습니다. 로딩/복구 표시, 터치 HUD, 한국어 조작 도움말과 키보드 포커스 처리를 지원합니다.

## 제작자 전용 배치 편집기 — Blender 없이 사용

프로젝트 폴더에서 `Open-Layout-Editor.cmd`를 실행하거나 다음 명령을 사용합니다.

```sh
npm run editor
```

`http://127.0.0.1:5174/tools/layout-editor.html`을 엽니다. 이 편집 서버는 **127.0.0.1에만 연결**되며 공개 게임의 `dist/`에는 편집 화면이나 저장 API가 포함되지 않습니다.

- 가구를 클릭하거나 목록에서 선택합니다. 이동/회전 손잡이를 드래그하거나 10cm 이동·15도 회전·크기 버튼, 위치 입력칸으로 조정합니다.
- 책상과 테이블을 옮기거나 복사하면 원래 연결된 기기·소품도 함께 따라갑니다. 복사본은 원본과 독립적으로 움직이고 파괴 점수도 각각 한 번씩 지급합니다.
- 삭제된 desk-20의 회색 칸막이는 독립 가구 `partition-72`로 복원되어 별도로 이동·회전·복사·삭제할 수 있습니다.
- **복사 / 삭제 / 되돌리기** 버튼과 `Ctrl+C`, `Ctrl+V`, `Delete`, `Ctrl+Z`를 사용할 수 있습니다. 성능을 위해 전체 오브젝트 수는 최대 200개로 제한합니다.
- **게임에 반영**을 누르면 `src/data/layout.json`을 저장하고 게임까지 다시 빌드합니다. 완료 후 `수정한 게임 열기`를 누릅니다. 저장 전 변경은 게임에 적용되지 않습니다.
- `처음 배치`는 편집 화면을 기본 배치로 돌립니다. 실제 파일을 바꾸려면 `게임에 반영`을 눌러야 하며, 저장 전 원본 파일은 `work/layout-backups/`에 자동 백업됩니다.

가구끼리 겹치지 않게 놓아 주세요. 벽·바닥·천장 밖으로 나가는 배치는 저장 전에 검사합니다. 공개 게임의 맵 복구는 제작자가 마지막으로 저장한 배치로 돌아갑니다.

## Blender / GLB — 선택 사항

`public/models/hnubs-main-room.glb`는 현재 저장한 배치의 가구와 바닥을 내보낸 정적 모델입니다. 기본 배치는 95개이며 복사·삭제한 경우 내보내는 수도 달라집니다. 각 가구 그룹 아래에 이름 있는 부품을 유지하고, ID·질량·점수·강도를 extras에 포함합니다. 편집용 모델에는 앱의 절차적 표면 텍스처, 벽 장식, 물리/게임 로직은 포함하지 않습니다.

Blender를 선호할 때 사용할 수 있는 별도 제작용 경로입니다. 공개 게임에는 배치 편집 버튼이나 편집 API가 없습니다.

1. 준비된 `blender/HNUBS-배치편집.blend`를 바로 엽니다. 방 경계와 스크린 위치는 참고용 와이어로 표시되어 있습니다. 또는 `File → Import → glTF 2.0`으로 `public/models/hnubs-main-room.glb`를 가져올 수 있습니다.
2. Outliner에서 `desk-1`, `wardrobe-…`, `coffee-…` 같은 **가구 부모 그룹(Empty)**을 선택합니다. `G`로 이동하고 `R → Z`로 수평 회전하고 `S`로 균일 확대·축소합니다. 책상 위 모니터·컵은 별도 그룹이므로 함께 옮길 때 같이 선택하세요.
3. 가구의 이름과 그룹 계층을 유지합니다. `File → Export → glTF 2.0`에서 형식을 **GLB**로 하고, `Selected Objects`를 끈 상태로 전체 씬을 `public/models/hnubs-edited.glb`에 내보냅니다. 기본 Y Up 설정을 유지하세요.
4. 이 프로젝트 폴더의 터미널에서 다음을 실행합니다. 기존 JSON 배치를 백업하고 새 배치를 검증한 뒤 게임까지 자동으로 재빌드합니다.

```sh
npm run import:layout
```

다른 경로의 파일도 지정할 수 있습니다.

```sh
npm run import:layout -- "C:/경로/수정한방송국.glb"
```

5. 게임 탭 `http://localhost:4173`을 새로고침하면 수정한 배치를 사용합니다. 최고 점수는 유지되고 진행 중인 판은 새로 시작합니다.

지원 범위는 **가구 그룹의 위치, 수평 회전, 0.2~3배의 균일 크기**입니다. 벽·바닥 밖으로 나가는 배치, 가구 그룹 이름 변경·삭제, 기울이기, 축별로 다른 크기는 오류로 알려줍니다. 새 메시 형상이나 추가 오브젝트는 `models.ts`에 별도로 반영해야 합니다. 배치 원본은 `src/data/layout.json`이고 자동 백업은 `work/layout-backups/`에 저장됩니다. 작은 소품을 다른 책상으로 옮길 때는 해당 상판 높이에 맞춰 배치하세요.

기본 배치로 돌아가려면:

```sh
npm run import:layout -- --reset
```

## 확인 범위와 다음 개선

실제 인앱 Chromium에서 데스크톱과 모바일 크기 화면, 배트·폭탄·레이저·음파, 점수 변화, 복구, 카메라 버튼 및 설정을 검사합니다. 저사양 실물 스마트폰과 Safari의 성능은 별도 확인이 필요합니다. Rapier의 WASM 초기화 과정에 라이브러리 내부의 deprecated-parameters 경고가 있을 수 있습니다. 첫 화면 코드와 물리/렌더링 코드는 분리 로딩되며, 렌더링/물리 번들의 압축 크기는 약 1.1MB입니다.

가장 효과적인 다음 작업은 실측 치수와 촬영 방향을 확인한 뒤 위치를 보정하고, 소파·의자를 Blender에서 더 정밀하게 다듬는 것입니다. 파괴는 사전 정의 부품 교체 방식이며 임의 단면을 실시간으로 절단하지 않습니다.

## 기술부스·아나부스와 작은 파편

메인룸 좌표와 저장된 배치는 그대로 두고 평면도 위쪽에 14×4m 부스 두 개를 확장했습니다. 사용자가 확인한 순서는 맨 위 아나부스, 그 아래 기술부스이며 내부 사진과 실측 전의 임시 구성입니다. `src/data/studios.ts`에서 위치·이름을 조정합니다. 기술부스에는 믹서·모니터·스피커·장비 랙, 아나부스에는 마이크·팝필터·책상·의자가 있습니다. 관찰창, 흡음벽, 문 통로와 절단면 표시를 포함합니다. 공간 보기 메뉴로 각 부스나 방송국 전체를 볼 수 있고 부스 장비도 제작용 편집기에서 이동·복사할 수 있습니다.

큰 상판·문짝·쿠션은 긴 축을 따라 작은 조각으로 나눠 흩어집니다. 회전과 부피를 보존하며 원통과 작은 부품은 형태를 유지합니다. 실시간 임의 단면 절단은 수행하지 않습니다. 파편 수명과 전체 상한으로 연쇄 폭발의 물리 부하를 제한합니다.

기존 `.blend` 파일은 메인룸 시점의 이전 편집본입니다. 새 부스 가구까지 포함한 현재 내보내기는 `public/models/hnubs-main-room.glb`를 사용하세요.

## PC·휴대폰 성능별 그래픽

화면 왼쪽 위 화질 메뉴에서 자동 / 저사양 / 균형 / 고화질을 선택합니다. 선택은 이 기기의 브라우저에 저장되며 게임 점수나 배치를 초기화하지 않습니다. 자동 모드는 터치 기기·낮은 CPU/메모리 정보에서 저사양으로, 나머지는 균형으로 시작합니다. 정보가 없으면 균형으로 시작하고 실제 렌더링 속도로 보정합니다. 로딩 직후와 숨겨진 탭은 측정에서 제외하고, 3초 평균이 연속으로 느리면 한 단계 낮추며 충분히 빠른 상태가 더 오래 유지될 때만 한 단계 올립니다. 수동 모드에는 자동 변경을 적용하지 않습니다.

| 설정 | 저사양 | 균형 | 고화질 |
|---|---|---|---|
| 최대 DPR / 렌더 픽셀 예산 | 1 / 약 65만 | 1.25 / 약 130만 | 2 / 약 240만 |
| 그림자 | 끔 | 1024px | 2048px + 부드러운 그림자 |
| 거울 실시간 반사 | 끔 | 256px | 1024px |
| 물리 파편 상한 / 유지 | 80 / 5초 | 180 / 8초 | 340 / 11초 |
| 동시 효과 상한 | 8 | 14 | 24 |

화면 크기에 따라 DPR을 추가로 낮춰 고해상도 휴대폰과 4K 모니터의 렌더 부하를 제한합니다. 품질을 낮추면 남아 있는 파편·효과도 즉시 상한까지 정리합니다. 게임 규칙과 점수·가구 배치는 같습니다. 제작용 편집기도 같은 성능 설정을 사용합니다. 기기별 실물 스마트폰 성능은 별도 검증이 필요합니다.

## 렌더링·물리 연산 최적화

반복 부품(CD 케이스, 랙 표시등, 가구 다리)은 InstancedMesh로 묶고 원래 위치·회전·재질을 유지합니다. 투명 유리와 불규칙 파편은 개별로 그립니다. 부서지기 전의 겹친 벽·문·평판 충돌체는 하나로 합치며 문틀 통로와 가구 다리 공간은 유지합니다. 실제 파손이 시작되면 남은 조각의 충돌체로 전환합니다. 파편 분할은 첫 타격 때 계산해 재사용하고 조각 지지 여부 판정의 경계 계산도 캐시합니다. 가루·시각 파편 배열은 재렌더링마다 다시 만들지 않습니다.

현재 저장 배치 225개에서 가구·내부 소품 모델의 렌더링 단위는 2,305→1,443(37.4% 감소), 초기 충돌체는 1,621→1,260(22.3% 감소)입니다. 이 수치는 전체 모델의 구조 집계로, 카메라 절단면·그림자·반사 패스를 포함한 GPU 실측 draw call 또는 FPS 향상률이 아닙니다. 실물 저사양 PC·휴대폰에서의 FPS 비교는 추가 측정이 필요합니다.

벽 파괴는 앞·속·뒷면을 같은 작은 구획으로 잘라 함께 제거합니다. 부품 원본의 UV 좌표를 파편에 누적해 흡음벽 줄눈과 게시판 그림이 늘어나거나 조각마다 다시 시작하지 않도록 했습니다. 잘린 옆면은 별도의 속재질로 표시합니다.

시작 화면은 ON AIR 표시등 점등 → 신호 막대 → 게임 전환 순서의 CSS 애니메이션입니다. 약 2.1초의 점등 연출과 실제 3D 준비가 모두 끝나면 0.45초 동안 사라집니다. 맵 복구에는 시작 연출을 반복하지 않고, 동작 줄이기 설정에서는 애니메이션과 최소 대기를 생략합니다.

### 사진 캐릭터와 연타 음성
메인룸의 원재 선배 캐릭터는 제공한 사진을 참고해 입체로 만든 얼굴·긴 머리·회색 털모자·초록 상의를 사용합니다. 공간 보기에서 `원재 선배`를 선택하면 가까이 볼 수 있습니다. 사람은 파편으로 분해되지 않고 타격에 반응합니다. 배트 기준 누적 25대에서 퇴장하고, 다른 무기는 배트 위력에 비례해 누적합니다. 연타를 쉬어도 누적 피해는 유지되며 맵 복구 시 캐릭터가 다시 등장합니다.
캐릭터를 맞힐 때 녹음이 순서대로 진행합니다. 현재 대사가 끝나기 전의 연타는 대사를 끊지 않으며, 2초 동안 타격이 없거나 맵 복구·탭 전환 시 처음으로 돌아갑니다. 마지막 단계는 반복합니다. 사운드를 끄면 진행 중인 음성도 멈춥니다.
원본 사진·음원은 `public/characters/`에 보존했고, 녹음의 쉼으로 추정한 6개 구간과 연타 간격은 `src/game/hitCombo.ts`에서 조정합니다. 얼굴은 사진 텍스처 없이 눈꺼풀·눈썹·코·입·볼·턱을 입체 메시로 구성하고, 모자 털은 인스턴스로 그립니다. 단일 사진에서 보이지 않는 옆·뒷면은 추정입니다.

### 업데이트 알림
`src/data/release.ts`의 `RELEASE.id`를 새 값으로 바꾸고 날짜와 변경 내역을 수정한 뒤 빌드하면, 새 버전 첫 접속 시 ON AIR 시작 화면이 끝난 다음 업데이트 카드가 뜹니다. 닫기·확인 버튼이나 Escape로 읽음 처리하며, 자동으로 사라지지 않습니다. 읽은 버전은 최고 점수·배치와 별개의 localStorage 키로 이 브라우저에 저장됩니다.

### 운석 무기
6번 또는 운석 버튼을 선택하고 지점을 클릭하면 4.4초 동안 근접 추적 → 충돌 지점 전환의 낙하 연출이 나오고 넓은 범위에 충격을 줍니다. 카운트다운·충돌 위치 표시·불꽃 꼬리·충격파·화면 흔들림을 포함하며, 연출이 끝나면 이전 카메라 시점으로 돌아갑니다. 동작 줄이기를 켜면 강제 시점 이동과 화면 섬광을 생략합니다. 진행 중 맵 복구 시 운석과 낙하음을 취소합니다. 운석 위력과 반경·지연 시간은 `src/weapons/meteor.ts`에서 조정합니다.
